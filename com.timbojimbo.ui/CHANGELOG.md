## [0.3.0] - 02/10/2026

UI Layout, Motion and Variants are part of this package, which now holds everything for building UI with UGUI.

### Added

- Layout (from UI Layout 0.5.0, `TimboJimbo.UI.Layout`): `LayoutNode`, a layout engine modelled on Clay: fit, grow, fixed and percent sizing, aspect ratios, wrapping and grids, floating against a parent, a root or another node, the safe area, show and hide effects (`DisplayEffect`), matched names that hand over or grow out of one another (`MatchName`, `MatchFit`, `MatchClip`), flights above every clip, and scrolling as a UIScrollView's (flicks, rubber banding, paging, snapping, anchors, indicators, nested drags, `ILayoutDraggable`). A node's `Animation` overrides a change's for the node and everything inside it, Inherit by default; `LayoutSystem.AnimationOf` says what a node moves on
- Motion (from Motion 0.1.0, `TimboJimbo.UI.Motion`): `MotionSystem.Animate`, as SwiftUI's withAnimation, moving what a change changes on springs from where it is drawn, with an animation of its own or the default; `MotionAnimation` (duration, bounce, curvature, delay; Smooth, Snappy, Bouncy, Arc and None presets, None no animation); `MotionTransition` (`Finished`, `Completed`, `Skip`, types, `Interactive`); `MotionSystem.AnimateValue` for values drawn by hand; `MotionSystem.Current`
- Variants (from Variants 0.2.0, `TimboJimbo.UI.Variants`): `VariantSet`, looks kept inside a prefab and switched in place, setting any serialized value, recorded by editing, previewed without saving; groups on Inherit, passed down the hierarchy by name; animated switches on a group's own animation; `VariantStates` for hover, press, focus and disabled on any object; `VariantBreakpoints` by drawn width, height or aspect ratio

### Changed

- One runtime assembly, `TimboJimbo.UI.Runtime`, and one editor assembly, `TimboJimboEditor.UI`, hold all of it; the UI Layout, Motion and Variants packages and their assemblies are gone
- `Img` is a layout node's content always (`ILayoutMeasurable`), not only with the UI Layout package installed (`TJ_UI_LAYOUT` is gone)

## [0.2.0] - 01/10/2026

### Added

- `Img` implements the UI Layout package's `ILayoutMeasurable` when that package (0.4.0 or later) is installed (optional reference, `TJ_UI_LAYOUT`), reporting its sprite's size, so an image is a `LayoutNode`'s content directly. It stretches with its rect as layout springs it to a new size

### Fixed

- `Box` builds in players: its `Reset` override is editor-only, as `Graphic.Reset` is
- `Box` and `Img` gradients no longer scramble into flickering hues when the graphic is rotated or scaled. The stops travelled packed in the vertex normal and tangent, which the canvas transforms by the graphic's rotation and scale when it batches; they now travel in texcoords, which it passes through as written, and neither component asks for the Normal or Tangent canvas channels. To make room, `Box` sends its corner radii as 12-bit fractions of its short side and its via position shares a float with the curvature; `Img` sends its blur step as two 12-bit log-scale values in one float, and a tiled `Img` its corners as rect-centred positions, the half size being their magnitude.

### Removed

- `Img`'s via stop (`GradientUseVia`, `GradientVia`, `GradientViaPosition`): its gradient is two-stop, since its texcoords have no room for a third once the stops leave the normal and tangent. `Box` keeps all three.
- `Img.TilePan`, the shader-time scrolling of a tiled grid, for the same room; animate `TileOffset` to scroll.

## [0.1.0] - 18/09/2026

### Added

- Box inspector: the Corner Radius and Inset rows have a lock button (like a Transform's uniform lock, default locked) that shows one value driving all four; unlocking reveals the four independent fields. The lock state is editor-only, not serialized
- Gradient inspector (Box and Img): the stops are edited on a live preview bar. From, To and (when Use Via Stop is on) Via show as chevrons; the Via chevron drags to reposition it and any chevron opens the colour picker on click. The preview evaluates the same RGB/HSV/OkLab/OkLCh interpolation the shader uses, over a checker so stop alpha reads correctly
- `Box.Masking` (`MaskMode`): None, DrawAndMask or MaskOnly. The box adds, configures and removes a `Mask` component to match (shown non-editable in the inspector, since the box owns it), so masking is one enum instead of a hand-wired Mask. MaskOnly renders the box as a crisp opaque white shape with colour, gradient and blur ignored (and those fields hidden in the inspector), so it writes a clean stencil without drawing; combined with `Inset` it clips immediate children to an inset shape with no padded wrapper
- Box inspector: Corner Shape is now a row of preset buttons (Circle/Parabola/Cosine/Cubic) instead of a dropdown, and a curvature between presets highlights none of them rather than showing a no-op "Custom" entry
- `Box.Concentric`: a box can inherit its corner radii and curvature from the nearest ancestor `Box`, matched per corner (parent radius minus the inset, or plus the outset when the child is larger than the parent, clamped at 0) so the rounded rects stay concentric in both directions. It resolves recursively for nested concentric boxes, tracks the parent live (radius, curvature, size or inset changes dirty concentric descendants), and mirrors the shader's CSS radius clamp in C# so the inherited values match what is drawn. Assumes child and parent share a canvas and axis alignment
- `Box.Inset`: offsets the drawn box within its `RectTransform`, uniformly or per side, in canvas units, with the corners kept concentric with the full rect. Positive shrinks it inward; negative grows it outward past the RectTransform (the corner radii grow to match). Only the generated mesh changes (RectTransform and layout untouched), so a `Mask` on the box stencils to the offset shape and its children mask to it without a padded child object. This also offsets the box's own fill; decoupling the stencil from the fill is left for a future soft-mask path
- `Box.StrokeWidth` accepts a negative width: the border ring draws outside the edge, spilling past the box (the quad grows to fit), instead of inside it. 0 still fills the box, positive is the inside (CSS border) ring
- `Box`: a `MaskableGraphic` that draws a signed-distance rounded box. Per-corner radii, a continuous corner curvature (circle → parabola → cosine → cubic) with presets, an inset stroke width, a blur radius and an offset. One instance is one effect: radii alone give a panel, blur plus a dark colour give a drop shadow, a stroke gives a border
- `Box` gradient fill: three stops (from, via, to) with an angle, a via position, per-stop colour and alpha, and the four `ColorInterpolationMode` options from the Property Bindings package (RGB, HSV, OkLab, OkLCh). OkLab and OkLCh blend in true linear light, matching `com.timbojimbo.core`'s `ColorExtra`. The whole gradient travels in vertex data, so gradient boxes still batch
- `TimboJimbo/UI/Box` shader and a shared material so every `Box` batches into one draw call
- Edge coverage eases across the transition band with a smootherstep (quintic) instead of a straight linear ramp, so blurred/soft edges fall off smoothly like a Gaussian blur rather than reading as a banded linear gradient, at the cost of only a polynomial
- Blend modes: `UiBlendMode` (Normal, Additive, Multiply, Screen) on `Box` and `Img`. Each mode resolves to its own shared material, so elements of the same component and mode still batch into one draw call while different modes are separate calls. The material inspector exposes a friendly Blend Mode dropdown via a `ShaderGUI`
- Corner radii clamp CSS-style: the limit on each corner comes from the two radii sharing an edge rather than half the box, so a full-height top radius with a square bottom is allowed. Corners are now evaluated around their own arc centre instead of folding at the box centre, so a radius larger than half the short side renders without a seam
- `Graphic.color` tints the whole gradient (it multiplies every stop) and CanvasGroup alpha fades every stop rather than only the first. The three stops travel packed in the vertex normal/tangent channels, leaving the colour channel free to carry the tint
- `Img`: an `Image` subclass with the same gradient tint and blend mode options as `Box`. Image builds the sprite geometry for every type (simple, sliced, tiled, filled, sprite mesh) and `Img` stamps the gradient descriptor onto those vertices, so the gradient is evaluated per pixel across the rect and multiplies into the sprite like `color` does. Ships with a `TimboJimbo/UI/Img` shader (UI/Default sampling, premultiplied output) and four shared blend-mode materials
- `Img` colour blend: `ColorBlendMode` (Multiply, Replace, Add, Screen, Darken, Lighten, Overlay, Difference) chooses how the colour or gradient combines with the sprite's own colour, and `ColorBlendFactor` fades between the untouched sprite and the blended result. Alpha is always sprite alpha times colour alpha, so Replace gives a silhouette recolour and the colour's alpha stays an opacity control
- `Img` blur: `BlurRadius` (canvas units) and `BlurQuality` (tap budget of up to 3×3, 5×5 or 7×7) blur the sprite in a single pass. The tap count grows with the radius toward the budget, and the taps sample the mip whose texel pitch matches their spacing so their footprints tile into a smooth result; cost is bounded by the quality rather than the radius, and a radius past the budget softens rather than getting more expensive. Simple sprites grow their quad so the blur spills past the sprite edge; taps are clamped to the sprite's atlas rect. The inspector warns when the texture has no mipmaps, when the blur reaches coarse mips of a block-compressed texture (compression streaks), and when a tap's footprint exceeds the atlas padding (neighbour bleed), naming the fix in each case. Blur and colour blend parameters travel in vertex data, so blurred and sharp images still share one material. At wide radii, where the blur samples a coarse mip, every tap is jittered independently by a fraction of a mip texel with an isotropic hash, turning the kernel into a stochastic estimate of a smoother one so the mip's facet grid dissolves into fine directionless grain (averaging across the taps keeps the grain low) instead of visible blocks; this is a per-component toggle (Img.BlurJitter, on by default) carried in vertex data, so toggling it keeps the shared material. A multi-pass (dual-Kawase) path for wide, perfectly smooth blur is left as a future option
- `Img.Texture`: a `Texture2D` field that shows a plain texture the way RawImage does, without a separate component. Img wraps it in a generated full-rect sprite (via `Sprite.Create`) driven through `overrideSprite`, so it takes precedence over Source Image while set and falls back to the sprite when cleared; only one renders at a time. The generated sprite is rebuilt on change and destroyed on disable, so nothing leaks
- Vertex-data packing is shared by both shaders: `UiPacking.cginc` (mirrored by `UiPacking` in C#) holds the colour-stop and integer-plus-fraction packing, and `UiGradient.cginc` the gradient maths. Packed values are exact at the vertices but interpolation can deliver them a hair off in the fragment stage (65279.998 for 65280), which split with a plain floor turned red into yellow and alpha 0 into opaque depending on the viewport size. Every decode now rounds before treating a value as an integer, and integer-plus-fraction values keep the fraction in a half range for headroom
- `Img` inspector: assigning a Texture whose asset is imported as a single Sprite offers to assign that Sprite instead, so its import settings (atlas, border, pixels per unit) apply rather than being bypassed by the generated wrapper sprite
- `Img` Tiled: the tile grid is drawn in the shader from a single quad instead of Image's one-quad-per-tile mesh. The grid only places stamps and the sprite settings say what is stamped there. Sprite: `TileSize` (width in canvas units, 0 = the sprite's native size, height follows the sprite aspect) and `TileSpriteRotation` (each stamp about its placement point, in canvas orientation, independent of the grid's rotation). Grid: `TileGridRotation` (moves the placement points about the rect centre), `TileSpacing` (distance between points per axis, 0 = the sprite size; below the sprite size each stamp is cut at its cell, so stamps never overlap), `TileStagger` (each successive row shifted along x and each successive column along y, as a fraction of the spacing; (0.5, 0) is brick), `TileOffset` (wraps every cell) and `TilePan` (canvas units per second on shader time, so a scrolling background never rebuilds its mesh; changing the rate re-phases the pattern). Each pixel belongs to the nearest placement point in lattice coordinates. The grid starts at the rect's bottom-left like Image's. The mip level comes from the continuous grid coordinate rather than the per-tile uv, so tile edges show no seams, and the blur steps through the same mapping so it flows across tile edges and gaps. The sprite border, Fill Center and Pixels Per Unit Multiplier are not used in this type
- Img's vertex data is repacked to fit the tiled layout without extra channels: the gradient mode, blur tap count, flags and colour blend mode share one header float with the gradient angle (`UiPacking.PackImgHeader`), the colour blend factor and the stagger share a float as 8-bit values (`UiPacking.PackTriple8`), the blur mip level is derived in the shader from the tap spacing instead of travelling per vertex, tiled quads carry their corner in uv0 so the position is derived from it, and the two rotations, spacing, offset and pan travel as 12-bit pairs relative to the sprite (`UiPacking.PackPair12`, 4096 steps, exact in a float)
- `Img` keeps every texture sample half a texel inside the sprite's atlas rect (scaled to the mip being read), so a scaled or tiled sprite no longer bleeds its atlas neighbours at the edges; the sharp path samples with the unclamped derivatives so the clamp does not sharpen edge pixels
- `SpriteAtlasMipBias`: applies a negative mip bias (default -0.5) to every Sprite Atlas texture as it registers at runtime, and re-applies it in the editor after atlas import and domain reload, so icons drawn well below their source size stay crisp instead of reading soft from the atlas's box-filtered mips. A Sprite Atlas exposes no mip bias or Kaiser filtering of its own, and the bias is a sampler state that cannot be baked into the atlas, hence the hook
